# Four-language benchmark results — 2026-11-24

## Summary

C, C++, Rust and CPython were tested on the same deterministic, single-threaded Conway's Game of Life workload. All four implementations produced the exact same final-state checksum in all three independent CI batches: 61ba73df36b48d49.

Across three GitHub-hosted runner batches, Rust had the lowest median time in every batch. C and C++ remained close to Rust, while the pure Python loop took roughly 200–245 times as long.

Across the three batches:
- Rust's median kernel time was about 5.5% lower than C.
- Rust's median kernel time was about 8.3% lower than C++.
- Python's median kernel time was about 223x Rust's.
- C and C++ were within roughly 3% of one another on the aggregate medians.

These are medians across only three CI batch medians, not a large statistical sample. Each batch itself reports the median of five measured samples.

## Workload and method

- Grid: 256 x 256 cells
- Generations: 80
- Total: 5,242,880 cell updates per sample
- Conway's Game of Life B3/S23 rules with toroidal boundaries
- Identical deterministic initial state and two-buffer update model
- Final FNV-1a checksum must match across all languages or the benchmark fails
- One warm-up and five measured samples per language, median reported
- Initialization, process startup, compilation and checksum calculation excluded from timed kernel
- Single-threaded, no third-party libraries

## Rust optimization observation

An initial Rust implementation using direct flat indexing measured 12.566 ms on an earlier separate run. Reworking the kernel to borrow row slices reduced subsequent measurements to 9.169 ms or below. This is a useful optimization observation, but not a controlled paired A/B test.

## Interpretation and limitations

This is one CPU-bound, single-threaded stencil workload. It does not establish a universal language ranking. Results can change with compiler versions, CPU model, flags, vectorization, data layout, algorithm and code shape. It does not measure memory footprint, startup latency, I/O, parallel scaling, optimized numerical libraries, application end-to-end performance or developer productivity.

The result supports a narrow conclusion: all three native implementations are dramatically faster than this straightforward Python-loop implementation, and the tested Rust kernel was slightly faster than the tested C and C++ kernels on this runner. It does not show that Rust is inherently faster than C/C++ in general.
